# Diagram Experience Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Preserve the session's native execution approach; use one fresh whole-branch reviewer at the end.

**Goal:** Integrate the approved diagram-only architecture and flowchart experience into the production compiler, viewer, editor, and agent workflow.

**Architecture:** Keep the current project loader, guarded saves, and shared browser compiler. Add a versioned source contract, pure geometry/routing functions, type-specific SVG preparation, and a reusable canvas controller. The viewer owns one exploration modal and navigation history; the editor continues to own the raw draft and save/conflict state.

**Tech Stack:** Existing Node.js >=22.18.0, erasable TypeScript, native DOM/SVG and `<dialog>`, ELK.js, esbuild, Node test runner, and Playwright/Chromium. Add no dependencies.

**Spec:** [Diagram experience](../diagram-experience.md). [Prototype evidence and limits](../prototype-readout.md). Primary source: commit `b8c4e35` on `prototype/diagram-experience`; inspect its `src/browser/diagram-experience.prototype.*` files with `git show`. Rewrite the behavior in production modules; the prototype is not a drop-in replacement.

## Global Constraints

- Implement architecture first, then flowcharts. Sequence, state machine, entity relationship, and dependency graph remain catalog entries; reject unsupported view types rather than render them as generic cards.
- Built HTML shows the diagram and optional legend, with no page header, permanent toolbar, sidebar, or prototype switcher. The live authoring page retains its save/status/graph controls.
- Details and internal views use one modal with Back history. Closing it restores the main diagram and keyboard focus.
- Show zoom/export controls on hover or focus. Provide an accessible menu toggle that also works with touch input.
- Initial scale is readable, with panning for large diagrams. Fit is an explicit action.
- Architecture nodes have a fixed size per view, optional top-left logos, concise titles, summaries, background colors, borders, and an internal-view indicator. Never shrink text merely to fit a node.
- Route priorities are readable labels/no forbidden overlaps, fewer crossings, shorter connections, then fewer bends. Geometry is generated by the compiler.
- SVG export contains the complete active view and optional legend, independent of viewport, without controls, details, modal frames, or selection styling.
- Preserve canonical nodes, references, custom data/templates, other views, exact-byte revision checks, recovery files, and dirty drafts. Source/asset changes update the live editor; application-code changes still require regeneration.
- Standalone HTML embeds all required views, styles, templates, and logos. Assets remain inert, local, and contained. No background network requests.
- `check` and `build` remain structural/asset checks. Keep `rendering: "not-verified"`; do not claim browser validation from a build alone.
- Keep this plan and its implementation on `feat/diagram-experience`, based on `f1439e9`. Include the plan with the eventual implementation PR. Do not create a planning-only PR. Keep `docs/superpowers/` ignored.

## Review Focus

1. The same canonical node, template, and logo may be visible in the root and modal at once; all SVG identifiers and local references must remain distinct: Tasks 2, 6.
2. Long Unicode text, large themed fonts, nonzero SVG viewBoxes, and tiny custom assets must not silently overflow fixed nodes, truncate titles, or lose full modal text: Tasks 2, 4, 5, 6.
3. A shorter route must not cut through an unrelated nested boundary, heading, node, label, or unrelated parallel connection; blocked cases must retain a valid baseline: Tasks 3, 4.
4. Dragging from text or a node must pan without selecting or activating it; actual clicks, keyboard activation, modal copying, and focus restoration must still work: Task 6.
5. Source edits, malformed assets, removals, and save replies arriving while a modal is open must preserve the last valid display/draft and avoid stale view context or re-enabled write controls: Task 7.

## Decisions made for this plan

These engineering choices turn the approved behavior into an implementable contract. They are not claims that the prototype already supports the production format.

- Add source version 2. Keep version 1 parsing, reading, editing, and saving without an automatic version upgrade. Normalize only for rendering. Existing v1 geometry/custom templates retain their measured sizing; v2 uses the new fixed-size rules. Both use the new diagram-only/modal viewer.
- Put diagram type and flowchart roles on views. A shared node can have different flowchart roles in different views. Store `mainPath` as ordered edge IDs to disambiguate parallel connections.
- Logos are optional `logos/NAME.svg` files. Use the existing inert SVG policy; no logo downloads, raster loading, or new icon dependency in this pass.
- Default architecture preset is `standard` (252 × 136). Also provide `compact` (224 × 128) and `large` (288 × 152). These extra preset dimensions are builder choices; the standard dimensions come from the prototype. Flowchart defaults match the prototype: action 222 × 84, decision 174 × 108, terminals 154 × 48.
- Keep the bounded route simplifier and ELK fallback. Do not promise a globally optimal or crossing-free result. The production pass must check more than the prototype's crossing count.
- Advanced authoring of views, boundaries, main paths, logos, and appearance remains file-based. Browser editing adds summaries, flowchart step kinds, and connection kinds/labels to the existing graph/text controls.

## Shared contracts

### Source and normalization — Task 1

Retain the existing structures under `DiagramNodeV1`, `DiagramEdgeV1`, `DiagramGroupV1`, `DiagramViewV1`, and `DiagramDocumentV1`. Existing exported names become unions where necessary. Common fields retain their names.

```ts
type DiagramType = 'architecture' | 'flowchart';
type NodeSizePreset = 'compact' | 'standard' | 'large';
type FlowStepKind = 'action' | 'decision' | 'start' | 'end';
type FlowDirection = 'down' | 'right';
type ArchitectureEdgeKind = 'call' | 'data' | 'event' | 'telemetry' | 'dependency';
type FlowEdgeKind = 'next' | 'branch' | 'error' | 'retry' | 'jump';
type ConnectionKind = ArchitectureEdgeKind | FlowEdgeKind;
type NodeAppearance = { background?: string; border?: string };
type DiagramNodeV2 = DiagramNodeV1 & {
  summary: string; logo?: string; appearance?: NodeAppearance;
};
type DiagramGroupV2 = DiagramGroupV1 & { parentId?: string };
type ArchitectureEdge = DiagramEdgeV1 & { kind: ArchitectureEdgeKind; label: string };
type FlowchartEdge = DiagramEdgeV1 & (
  | { kind: 'next'; label?: never }
  | { kind: Exclude<FlowEdgeKind, 'next'>; label: string }
);
type ViewBaseV2 = Omit<DiagramViewV1, 'edges' | 'groups'> & {
  groups?: DiagramGroupV2[]; legend?: boolean;
};
type DiagramViewV2 = ViewBaseV2 & (
  | { type: 'architecture'; edges: ArchitectureEdge[]; nodeSize?: NodeSizePreset }
  | { type: 'flowchart'; edges: FlowchartEdge[];
      stepKinds: Record<string, FlowStepKind>; mainPath: string[];
      direction?: FlowDirection }
);
type DiagramDocumentV2 = Omit<DiagramDocumentV1, 'version' | 'nodes' | 'views'> & {
  version: 2; nodes: Record<string, DiagramNodeV2>;
  views: Record<string, DiagramViewV2>;
};
type DiagramDocument = DiagramDocumentV1 | DiagramDocumentV2;
type DiagramNode = DiagramNodeV1 | DiagramNodeV2;
type DiagramEdge = DiagramEdgeV1 | ArchitectureEdge | FlowchartEdge;
type DiagramGroup = DiagramGroupV1 | DiagramGroupV2;
type DiagramView = DiagramViewV1 | DiagramViewV2;
```

`parseDocument(value: unknown): DiagramDocument` validates and returns the raw source; it never upgrades or drops fields. V1 rules stay unchanged. V2 keeps unknown-field rejection and the existing ID/reference rules. Colors accept only hex RGB/RGBA forms with 3, 6, or 8 hexadecimal digits. `logo` is an asset ID, not a path or URL.

In v2, architecture labels are nonempty. Every flowchart member has exactly one `stepKinds` entry; orphan entries are invalid. Outgoing decision edges use a labeled outcome (`branch`, `error`, `retry`, or `jump`), not `next`. Those four kinds always require nonempty labels; ordinary `next` edges have no `label` field. `mainPath` is present, may be empty for an authored fragment, and otherwise lists unique existing edge IDs in a contiguous, non-repeating-node chain. Ordinary graph cycles/self-edges remain valid outside that main path. Group parents exist within the same view and are acyclic. Nodes belong to at most one direct group; ancestor containment is implicit.

`normalizeDocument(document: DiagramDocument): RenderDocument` validates and creates rendering data without changing the input. Define `RenderNode = DiagramNodeV2`, `RenderEdge = DiagramEdgeV1 & { kind: ConnectionKind }`, and `RenderDocument` with the existing document metadata/nodes/views, omitting the source version. Each `RenderView` has the existing title/detail/node IDs plus `type`, `edges: RenderEdge[]`, `groups: DiagramGroupV2[]`, `legend: boolean`, `nodeSize: NodeSizePreset`, `direction: 'auto' | FlowDirection`, `stepKinds`, `mainPath`, and `legacySizing: boolean`.

Defaults: v1 → architecture, `legacySizing: true`, empty summaries, `call` edges with original optional labels, flat groups, legend enabled. V2 → `legacySizing: false`, legend enabled unless false, standard architecture size/automatic direction, or downward flowchart direction. Empty views remain valid. Raw snapshots/drafts/saves always retain the author's source version.

### Geometry, routing, nodes, layout — Tasks 3–5

```ts
type Point = { x: number; y: number };
type Size = { width: number; height: number };
type Rect = Point & Size;
type SceneNode = Rect & { id: string; groupId?: string };
type SceneGroup = Rect & { id: string; parentId?: string; header: Rect };
type SceneLabel = Rect & { text: string; lines: string[] };
type SceneEdge = { id: string; source: string; target: string;
  kind: ConnectionKind; paths: Point[][]; labels: SceneLabel[] };
type LayoutScene = { nodes: SceneNode[]; groups: SceneGroup[]; edges: SceneEdge[] };
type ViewMeasurements = { nodes: Record<string, Size>;
  edgeLabels: Record<string, { width: number; height: number; lines: string[] }>;
  groupLabels: Record<string, Size> };
type RouteMetrics = { overlaps: number; crossings: number; length: number; bends: number };
```

- `assessRoutes(scene: LayoutScene): RouteMetrics`, `compareRoutes(a: RouteMetrics, b: RouteMetrics): number`, and `shortenRoutes(scene: LayoutScene): LayoutScene` live in `routing.ts`. Coordinates are absolute, IDs are canonical, and inputs remain unchanged. Forbidden overlaps include node/label contacts, edge entry into unrelated nodes/boundaries/headings/labels, and substantial collinear hiding of unrelated connections. Endpoint border contact and shared endpoint trunks are allowed. Count genuine orthogonal interior crossings separately.
- Shortcuts try cardinal side anchors and obstacle-edge corridors, at most two turns, with 10-unit node, 12-unit unrelated-boundary, and 6-unit heading/label clearance, 16-unit endpoint stubs, and 8-unit label offset. Labels must fit along their associated segment. Only accept a shorter route with fewer bends, no forbidden contacts, and no additional crossings. Preserve complex/multiple-section/self-loop routes when no safe shortcut exists.
- `prepareNode(input: ProjectInput, document: RenderDocument, viewId: string, nodeId: string, scope: string, stage: SVGElement): Promise<{ svg: SVGSVGElement; bounds: Rect; size: Size }>` lives in `nodes.ts`. Measure with actual applied SVG/CSS/fonts. V2 cards reserve 16-unit padding, a 32-unit optional logo, at most two title lines, and at most three summary lines within the remaining area. Reject a title that cannot fit; truncate summaries with an ellipsis and preserve full source text for the modal. Keep v1's measured wrapping/sizing.
- `layoutCandidates(document: RenderDocument, viewId: string, measurements: ViewMeasurements): Promise<LayoutScene[]>` lives in `layout.ts`. Architecture tries right/down directions and 34/48-unit spacing; nested groups reserve measured headings. Flowcharts try left/right branch sides at 34/48 spacing, following the view's direction and main-path edge IDs. All coordinates and ports are generated here.
- Measure and wrap connection labels to a 128-unit maximum width before layout; break long text without splitting Unicode characters. Fit those measured blocks beside clear segments rather than lengthening routes for an unwrapped line.
- `compileView(input, viewId, host): Promise<CompiledView>` and `exportSvg(view): string` retain their current signatures and `{ viewId, svg, bounds }` result. The compiler selects the best measured candidate, simplifies architecture detours, and draws the SVG/optional legend. Never serialize viewport transforms or application UI as diagram content.

### Canvas, viewer, editor — Tasks 6–7

`canvas.ts` exports `Camera = { x: number; y: number; scale: number }` and:

```ts
mountCanvas(host: HTMLElement, view: CompiledView, options: {
  onNode(nodeId: string): void; onExport(): void; initialCamera?: Camera;
}): { getCamera(): Camera; focus(nodeId?: string): void; destroy(): void };
```

Put project SVG/styles in a shadow root; put HTML controls outside that style scope. Default readable scale is `min(1, max(0.9, fitScale))`; center each axis that fits and pan the others. Fit is explicit. Use a four-pixel drag threshold, delayed pointer capture, primary-button handling, and click suppression after dragging. Disable selection only on the diagram canvas. Accessible controls are `Zoom out`, `Zoom in`, `Fit`, `Readable`, and `Export SVG`. When the canvas itself is keyboard-focused, arrows pan; do not intercept typing in detail/editor fields.

Retain `ViewerHandle = { update(input: ProjectInput): Promise<void>; currentViewId(): string; destroy(): void }`. `mountViewer` keeps `initialViewId`, `onViewChange(viewId)`, and a details hook extended to `renderDetails(host: HTMLElement, nodeId: string, viewId: string): void`. Add optional `renderAuthoringControls(host: HTMLElement, viewId: string, mode: 'diagram' | 'details'): void`. The active view is the last diagram context in modal history, including when its node details are open; closing the modal restores the root context. Notify the editor before rendering details or rebuilding active-view controls.

Invoke the authoring-controls hook in the root and active modal frames. The editor renders Save/status/conflict actions in both, and graph controls in diagram frames. Root controls remain mounted and inert behind the native dialog, preserving root size/camera. Bind controls to the frame's view ID and the shared draft/save state; use unique input IDs per frame. Do not move the only save/conflict controls behind an inert backdrop. Standalone viewers supply no hook and render no authoring UI. A modal header provides the active-view export action even when its body displays node details.

`edit-graph.ts` exports `removeNodeFromView(document, viewId, nodeId): void`, `removeConnectionFromView(document, viewId, edgeId): void`, and `repairMainPath(path: readonly string[], edges: readonly DiagramEdgeV1[]): string[]`. Repair retains the longest surviving contiguous run of the authored edge IDs, with the earliest run winning ties. Never infer new main-path edges or alter another view.
